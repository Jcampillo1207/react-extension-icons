## Install

```bash
npm install react-extension-icons
```

`react` (`^18 || ^19`) is the only peer dependency, and the package has none of its own.
Ships ESM and CommonJS builds plus TypeScript declarations.

## Quick start

```tsx
import { Icon } from 'react-extension-icons';

export function Attachment({ filename }: { filename: string }) {
  return (
    <span>
      <Icon extension={filename.split('.').pop() ?? ''} size={20} />
      {filename}
    </span>
  );
}
```

`extension` is case insensitive and the leading dot is optional — `pdf`, `PDF` and `.pdf`
all resolve to the same icon. An unknown extension renders nothing, so there is no
placeholder to design around.

## Choosing an import style

Both styles render the same markup. The difference is what ends up in your bundle.

```tsx
// 1. Runtime lookup — use when the extension is only known at runtime.
import { Icon } from 'react-extension-icons';
<Icon extension={file.ext} />

// 2. Named import — use when you know the icon at build time.
import { PdfIconColor } from 'react-extension-icons';
<PdfIconColor width={24} height={24} />

// 3. Subpath import — same as 2, and skips the barrel entirely.
import PdfIconColor from 'react-extension-icons/icons/color/PdfIconColor';
```

| Style | Bundled (gzip) | Why |
|-------|----------------|-----|
| `<Icon>` | ~200 KB | Looks icons up by string, so it has to reference all 120 components. |
| Named import | ~3 KB | Tree-shaken. |
| Subpath import | ~2 KB | Tree-shaken, and never loads the barrel. |

Measured with esbuild against a single icon. If you only ever show a handful of file
types, prefer styles 2 and 3; reach for `<Icon>` when the extension comes from data.

## Variants

```tsx
<Icon extension="pdf" variant="color" />       {/* default */}
<Icon extension="pdf" variant="grayscale" />
<Icon extension="pdf" variant="single_color" color="#7c3aed" />
```

`color` only affects `single_color`, which is drawn in a single accent tone. Leave it off
and the variant falls back to its default accent. On the `color` and `grayscale` variants
the prop is ignored and no stray attribute is emitted.

The equivalent named imports are `PdfIconColor`, `PdfIconGrayscale` and
`PdfIconSingleColor` — every icon in the gallery follows that pattern.

## Accessibility

Icons are decorative by default and carry `aria-hidden="true"`, which is what you want
next to a visible filename. Give one a name only when it is the sole carrier of meaning:

```tsx
{/* decorative — the filename next to it already says "report.pdf" */}
<Icon extension="pdf" /> report.pdf

{/* meaningful — nothing else identifies the file type */}
<Icon extension="pdf" title="PDF document" titleId="pdf-title" />
<Icon extension="pdf" aria-label="PDF document" />
```

Passing `title`, `aria-label` or `aria-labelledby` drops `aria-hidden` automatically.

## Server rendering

The components hold no state, call no hooks and touch no browser APIs, so they render
during SSR and static export without a `"use client"` boundary. Attaching a `ref` is the
one thing that requires a Client Component, as with any React element.

## API

### `<Icon>`

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `extension` | `string` | — | File extension, with or without a leading dot. |
| `variant` | `'color' \| 'single_color' \| 'grayscale'` | `'color'` | Which artwork to render. |
| `size` | `number \| string` | `24` | Width and height. Explicit `width`/`height` win. |
| `color` | `string` | — | Accent color. `single_color` only. |
| `title` | `string` | — | Accessible name. Pair with `titleId`. |
| `titleId` | `string` | — | id for the `<title>`, wired up via `aria-labelledby`. |
| `ref` | `Ref<SVGSVGElement>` | — | Forwarded to the underlying `<svg>`. |

Every other `svg` prop — `className`, `style`, `onClick`, `data-*`, `role` — is forwarded
to the `<svg>` element.

### Individual icon components

Same props minus `extension`, `variant` and `size`; set `width` and `height` directly.
`color` only has an effect on the `*IconSingleColor` components. All of them forward refs.

### `getIconComponent(extension, variant?)`

Resolves a component without rendering it. Returns `null` for unsupported extensions.

```tsx
import { getIconComponent } from 'react-extension-icons';

const PdfIcon = getIconComponent('.PDF', 'grayscale');
```

### `extensionMapping`

The extension-to-icon lookup table, exported so you can check support up front:

```tsx
import { extensionMapping } from 'react-extension-icons';

const isSupported = (ext: string) => ext.toLowerCase() in extensionMapping;
```

### Types

`IconProps`, `IconComponent`, `IconSvgProps` and `Variant` are all exported.

## Contributing

Everything in `src/` is generated from the SVGs in `svg/`. Edit the artwork, never the
components — `npm run generate-icons` overwrites them.

```bash
npm run generate-icons   # svg/ -> src/
npm run typecheck
npm run build            # src/ -> dist/{cjs,esm,types}
npm test
npm run verify           # all four, in order
```

To add an icon:

1. Drop `NAME.svg` into `svg/color/`, `svg/single_color/` and `svg/grayscale/`.
2. Add its extensions to `extensionMapping` in `scripts/generateIcons.js`.
3. Add a row to the extension reference above.
4. Run `npm run verify`.

The `single_color` artwork must use `#5659E9` as its accent — that is the value swapped
out for the `color` prop, and generation fails if an icon is missing it. Icon ids are
prefixed per component during generation; do not hand-edit them, or two icons on the same
page will collide.

### Releasing

```bash
npm run release   # verify, version patch, push with tags, publish
```
